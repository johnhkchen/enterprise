# Game tests sorted for the binding

Generated by `python3 scripts/parity.py --binding` (docs/binding-plan.md section 2); do not edit by hand. Each `@GameTest` is one of:

- **World fixture** (155): builds or reads blocks, spawns villagers or players, or waits on the game clock, then asserts an outcome in the world. These become the binding's acceptance tests, rewritten where they call a Java rule so they drive the core through the binding; green in core mode is a concern's gate.
- **Rule API** (66): calls Java rule classes on plain data, no world to speak of. Retired with the class they pin; the Rust twin (a `parity:` tag) stands in. One with no full twin has to move to the core first.
- **Minecraft's own** (77): listed in `scripts/parity-skip.txt`; blocks, entities, the client. Kept as the binding's view tests.

298 tests. A test is a fixture if its body (or a helper it calls, in its own file or another test file's) uses `setBlock`, `spawn`, block or entity reads, mock players, sequences, `succeedWhen` or discards an entity; a skip-listed test is Minecraft's own whatever its body does. A spawn or block read inside a Java rule class isn't seen, so a rule-API test marked *level* below hands the level to a rule: check that rule doesn't read the terrain before retiring the test (27 of them).
